## PIE TIME (picoCTF, binary exploitation, Easy)

For this challenge, I was given three things: a remote server connection command, a binary file, and a source code file that allowed me to read the code of the binary file. First, I tried running the remote program to find out that it wanted me to enter the address I wanted to "jump to". I assumed that either meant "jump to" the address of the flag or jump to the address of a function that outputs the flag. From there, I took a look at the source code of the binary file to find out that the goal was to run the `win()` function, so the flag could be outputted. I remembered that the program wanted me to input an address, so I decided to try to look for the address of the `win()` function. I ran `nm` on the binary file to get more information on the `win()` and `main()` functions. I found that they were `0x96` bytes away from each other. Because of PIE every time the remote program is called, the program is run at a different location in memory; however, `main()` and `win()` still stay `0x96` bytes apart, with `win()` being before `main()` in memory. With this information, I ran the remote program again, but this time I just subtracted `0x96` bytes from the randomly generated main address, to get the `win()` address in hexadecimal and get the flag. This challenge mainly taught me about how PIE is a safety feature that makes programs run at a different place in memory each time to weaken Return-Oriented Programming (ROP) exploits.
